# VERIFICATION — how to verify / QA
- Playwright is unavailable here, so qa/smoke.mjs runs on jsdom: JS syntax, DOM structure, engine init flags (`__A`/`__B`), the selection popup, the highlight Ctrl gesture gate, `#hlLayer` paint separation, the colour palette, Ctrl+click delete and the layer-independence rule. jsdom has no layout, so the suite installs a deterministic fake layout (8px/char, 40 chars/line, 20px/line) to exercise rectangle geometry and the hit test — it does NOT cover real rendering, media, or actual mouse/keyboard events.
- Real input/timing bugs (e.g. the held-Ctrl auto-repeat palette bug) CANNOT be caught by jsdom — QA stayed green while the live page was broken. When a report mentions timing, auto-repeat, real mouse/keyboard or on-screen position, drive a real headless Chrome over the DevTools Protocol: qa/live.mjs (throwaway probe: `--headless=new --remote-debugging-port=0`, `Input.dispatchMouseEvent`/`Input.dispatchKeyEvent`, `Runtime.evaluate` to read `getBoundingClientRect`). qa/live.mjs = real Chrome over CDP, zero npm dependencies.
- Scope QA to what changed (HARNESS.md RULE 4): qa/content.mjs (structure), qa/overflow.mjs (layout) and qa/width.mjs (width/division) accept one or more lesson numbers — `node qa/content.mjs 5`, `node qa/overflow.mjs 5`, `node qa/width.mjs 5` — and with no numbers they sweep every `business/lesson*.html` that exists (an empty business/ passes; a named lesson with no page fails). qa/smoke.mjs exercises each existing business page's interactive features. Both markup audits carry a fixture selftest: `node qa/width.mjs --selftest` and `node qa/overflow.mjs --selftest` (the latter is green only if qa/fixtures/overflow-ok.html is clean AND overflow-bad.html reports findings, so a harness that measures nothing can never pass). `npm run qa:layout` runs the overflow selftest and then the sweep. Content/layout changes (lesson HTML, style.css) MUST run the real-browser overflow/balloon check — jsdom cannot see layout.
- qa/width.mjs audits the block model (FORMAT.md): every `.itemsize-half` / `.itemsize-third` sits inside a `.itemrow` and never carries both; a `.itemrow[data-cols="2"|"3"]` holds exactly 2 halves / 3 thirds, with no mixing and no inline width on a member; retired classes and chart column counts are refused. The content-aware freedom *inside* a block (how many columns a chart or a list takes) is deliberately not column-count-checked — the content decides.
- qa/overflow.mjs measures, in real Chrome, the block model FORMAT.md defines: OVERFLOW (content wider than its block), BALLOON (a block wider than its slot — `.itemsize*` / the row's `data-cols`), ESCAPE (any element crossing the fixed `.content-area` frame, which is how a right-aligned `.blanks` item spilling LEFT out of its panel shows up), CELL (a `.blanks` cell whose item cannot fit) and RESIZE (a `textarea` inside `.content-area` that the student can still drag — a free-text block is fixed size) and SELECT (a shell element — `header.brand`, `.control-bar`, `#barhelp`, `footer` — that is still selectable; the notebook exists only inside `.content-area`) and LEGEND (the `#barhelp` legend wrapping past one line) and the vertical rhythm of the page (BLOCKGAP / ROWGAP / OPTGAP / CHARTPAD — a block, row member, option pair or chart cell with less space than FORMAT's rule allows); DEADSPACE and HEIGHT are printed as review-only hints. Row completeness is qa/width.mjs's job. It prints what it measured and the minimum space found (`canvas … · blocks N (full / half / third)` + `spacing (min): between blocks … row members … options … chart cell padding …`), so both "it measured nothing" and "the spacing is gone" are visible in the output. `--shot <file> [--shot-h <px>]` also saves a picture of the page top, as a review aid when a check fires or a new element needs an eyeball.
- qa/content.mjs also prints a non-failing `(hint)` when two distinct controls resolve the same answer anchor (a radio group counts as one control) — such fields are only separated by the `{block,offset}` tie-breaker, so a re-order can swap their saved answers.
- `raw.githubusercontent.com` caches branch-name fetches briefly — verify fetched content by commit SHA when in doubt.
