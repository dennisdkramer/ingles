# FILESYSTEM — repository map
- root: index.html · style.css · engine1.js · engine2.js · dictionary.json · pronkey.js · build-dictionary.js · top50000_english.txt · logo.png · access.json · .gitignore · package.json
- spec/rule files: HARNESS.md (read-first hub + rules) · PENDING.md (active subtask plan) · PARKED.md (backlog of queued/parked work) · HANDOFF.md (session handoffs) · ISSUES.md (bugs/problems) · FUNCTION.md (behaviour + backend + edit mode) · FORMAT.md (site structure & formatting) · PEDAGOGY-MAP.md (per-lesson roadmap + generation process/defaults + track personas) · PEDAGOGY.md (teaching side) · VOCABULARY.md (concept inventory) · STATUS.md (state & shared parameters) · VERIFICATION.md (how to QA) · FILESYSTEM.md (this map)
- pages: business/ (the live business track, lessons 1-50 as they are generated) — designs/ (Pass-A design doc per lesson) — audio/ (pre-rendered TTS clips + manifest.json, written by build-audio.mjs) — backend/Code.gs — qa/smoke.mjs (jsdom suite, run with `node qa/smoke.mjs`) — qa/landing.mjs (index.html / student index structure, jsdom) — qa/content.mjs (structure) — qa/overflow.mjs (layout, real Chrome) — qa/width.mjs (width/division audit, markup-only; `node qa/width.mjs --selftest`) — qa/live.mjs (real-Chrome CDP harness, run with `node qa/live.mjs`) — node_modules/ (untracked, gitignored)
- `lessons-archive/`, `kids/` and `adult/` are **untracked and gitignored**: they hold the old pre-rewrite lesson pages and are deliberately withheld from lesson generation (owner instruction 2026-11-03). They stay on the owner's disk but must not be opened, read or used as a reference for content, structure or layout — a lesson's shape is imagined from `designs/lessonNN.design.md` + PEDAGOGY-MAP.md. `build-lessons.mjs` skips a track whose folder is gitignored, so `lessons.json` only advertises pages that are actually in the repo. `style.css` is implementation only for the same reason.
- track folders are created by generating a lesson into them; a track re-enters the manifest automatically once its folder is tracked (committed) again.
- A file that the current batch does not reference is assumed fully functional; only a verification step proves otherwise.
