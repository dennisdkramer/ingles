# FILESYSTEM — repository map
- root: index.html · style.css · engine1.js · engine2.js · engine3.js · dictionary.json · pronkey.js · build-dictionary.js · top50000_english.txt · logo.png · access.json · .gitignore · package.json · _shell.html (the ONE page shell, with `{{TRACK_TITLE}}` / `{{TRACK_UPPER}}` / `{{TRACK}}` / `{{L}}` / `{{LESSON_TITLE}}` placeholders — every lesson is built on it, never on another lesson's shell)
- spec/rule files: HARNESS.md (read-first hub + rules) · PARKED.md (backlog of queued/parked work) · HANDOFF.md (session handoffs) · ISSUES.md (bugs/problems) · FUNCTION.md (behaviour + backend + edit mode) · FORMAT.md (site structure & formatting) · IMPLEMENTATION.md (the build manual: what each class/knob does, the mechanics behind it — tiling, print, paint layers, answer keying — the QA enforcement map, the hard limits and the dated owner specs migrated out of style.css) · PEDAGOGY-MAP.md (per-lesson roadmap + generation process/defaults + track personas) · PEDAGOGY.md (teaching side) · VOCABULARY.md (concept inventory) · STATUS.md (state & shared parameters) · VERIFICATION.md (how to QA) · FILESYSTEM.md (this map)
- pages: kids/ · business/ · adult/ (the three live tracks, lessons 1-50 as they are generated) — designs/ (Pass-A design doc per business lesson; `designs/kids/`, `designs/adult/` for the other two tracks) — audio/ (pre-rendered TTS clips + manifest.json, written by build-audio.mjs) — backend/Code.gs — qa/smoke.mjs (jsdom suite, run with `node qa/smoke.mjs`) — qa/landing.mjs (index.html / student index structure, jsdom) — qa/content.mjs (structure) — qa/overflow.mjs (layout, real Chrome) — qa/width.mjs (width/division audit, markup-only; `node qa/width.mjs --selftest`) — qa/games.mjs (engine3.js / shootPair state machine, jsdom) — qa/live.mjs (real-Chrome CDP harness, run with `node qa/live.mjs`) — qa/track.mjs (the one place a harness learns its SCOPE: no `--track` = every track that has pages, `--track=kids|business|adult` narrows it) — node_modules/ (untracked, gitignored)
- `kids/` and `adult/` are **tracked** and generated from their own designs; `build-lessons.mjs` skips a track whose folder is gitignored, so `lessons.json` only advertises committed pages. A lesson's shape is imagined from `designs/lessonNN.design.md` + `PEDAGOGY-MAP.md`, never copied from another page; `style.css` is implementation only.
- track folders are created by generating a lesson into them; a track enters the manifest once its folder holds committed pages (`node build-lessons.mjs`).
- A file that the current batch does not reference is assumed fully functional; only a verification step proves otherwise.
