# FILESYSTEM — repository map

- SPEC/RULE FILES: .clinerules/.clinerules.md · FUNCTION.md (behaviour + backend + edit mode) · style.css `/* #` headers (the lesson-facing contract in words: page order, blocks, classes, markup) · STATUS.md (state & shared parameters) · FILESYSTEM.md (this map)

- WORKING PLAN: PENDING.md (the active subtask batch plan, HANDOFF.md (new task handoffs (when requested)

- LESSON GENERATION: PEDAGOGY-MAP.md (generation process and rules) , `qa/AUDIO.md` (the audio cut: routes, flags, steps, and the fix for a sync that is off) and `qa/pos.mjs` (the tagger that emits the `.pos-*` marks a page pastes) , `qa/checks.mjs` read by name — `read qa/checks.mjs [WRAP]` (THE THREE-LEVEL WRAP: puts every node of a page into a cell and a row, three levels deep — `node qa/checks.mjs wrap <page…>` reports, `--write` rewrites, `--check` refuses a page that is not wrapped; it re-emits each element from its own raw tag so no attribute is lost, and it is a fixed point, so running it twice adds nothing) , `<TRACK>-ROADMAP.md` (one `##` section per lesson) · `<TRACK>-REGISTER.md` (the persona) · `extra/lesson1-The Capability Map.html` (the map: every shape a page is built from — §1 the three passes, §2 prose, §3 the visual index, §4 the in-block elements, §5 the activities; its open `details.reveal` specimens are the markup contract) · `_shell.html` (the frame every lesson page starts as: a generation copies it into the track folder and authors into it) · VEHICLES.md, IN-BLOCK-VISUALS.md and CONTENT_EXAMPLES.md remain in the repo but are no longer generation inputs

- TRACK ROADMAPS: ROADMAP-GENERATOR.md (produces the roadmaps — a separate pipeline)

- LESSON TRACKS/PAGES: one folder per track (kids/ · business/ · adult/ today, plus six empty test tracks: advanced-stem/ · advanced-aave/ · memelord-mogger/ · english-basic-portuguese/ · gramatica-redacao/ · linguagem-figurativa-giria/) — a track folder holds `lesson<N>-<Title>.html` (the filename carries the lesson's number AND its title, spaces and all; nothing reads a page to learn its title) plus an optional track.json {label, icon, color, order}; `label` is the display name and `icon` its emoji

— BACKEND: Code.gs — **`qa/checks.mjs` is EVERY lesson-page check in one file, read BY NAME** (`read qa/checks.mjs [CHECK 2]`), never by line span: `[QA OFF]` the kill switch · `[SCOPE]` where a run reads (the discovered tracks, the lesson files, the ONE static server) · `[WRAP]` the three-level wrap's rule and writer · `[CHECK 1]` the prose, from the map page's own `Checks` bullets · `[CHECK 2]` THE page gate: structure, blocks, items, markup boxes, the wrap, the block sequence against the roadmap ledger lines, and the runtime · `[ALIGN]` the end-of-batch pass: rendered geometry, and the reader marks the Portuguese and writes the quiz · `[LIVE]` real Chrome over CDP · `[GAMES]` engine4's state machine · `[INDEX]` the derived files (not a check) · `[QUEUE]` the finding shape and the one idempotent PENDING write · `[CLI]` `node qa/checks.mjs <fn> …`. Scope: no flag reads the ONE track the working tree touches (two touched tracks is a refusal), `--track`/`--lessons`/`--page`/`--all` narrow or widen it, `--all` is the only sweep — qa/landing.mjs (index.html / student index structure, jsdom; imports `qaOff` from `qa/checks.mjs`) — qa/liquid.mjs (the `.md` publish guard the pre-push hook runs first) — qa/rows3.mjs (the layout editor's four drop shapes in real Chrome, on `qa/fixtures/rows3.html`, and undo after each; `node qa/rows3.mjs` with QA_ON=1) — qa/serve.mjs + qa/NOTES.md (preview-only) — node_modules/ (untracked, gitignored)
