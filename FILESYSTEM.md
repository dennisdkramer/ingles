- spec/rule files: .clinerules/.clinerules.md (tool discipline + prompt parsing + batching) · HANDOFF.md (session handoffs) · FUNCTION.md (behaviour + backend + edit mode) · PEDAGOGY-MAP.md (generation process + defaults — rules only) · style.css `## ` headers (the lesson-facing contract in words: page order, classes, markup, appearance) · STATUS.md (state & shared parameters) · VERIFICATION.md (how to QA) · FILESYSTEM.md (this map)

- generation: `qa/brief.mjs` (a PRINTER, not a check: `--track=<t> --lesson=<n>` prints [I/O]'s input set in reading order, `--reassert` reprints the map, `--section=<name>` prints one chosen shape in full) · PEDAGOGY-MAP.md [I/O] (the mandatory inputs, their precedence, and the ~40 KB context budget) · `<TRACK>-ROADMAP.md` (one `##` section per lesson) · `<TRACK>-REGISTER.md` (the persona) · CONTENT_EXAMPLES.md (the vehicle menu: the `###` lines are the index, one section is read only after a shape is chosen) · `_shell.html` (the page a build fills) · ROADMAP-GENERATOR.md (produces the roadmaps — a separate pipeline, never read by a lesson build) · `.edit.html` sidecars (a byte-identical copy beside each page, made by the edit flow)
- pages: one folder per track (kids/ · business/ · adult/ today, plus six empty test tracks: advanced-stem/ · advanced-aave/ · memelord-mogger/ · english-basic-portuguese/ · gramatica-redacao/ · linguagem-figurativa-giria/) — a track folder holds lesson*.html plus an optional track.json {label, icon, color, order}; `label` is the display name and `icon` its emoji, the ONLY places they live, and `color` is the 200 swatch the teacher's access switch fills with. **A folder's NAME is URL-, selector- and CLI-safe** — lowercase with hyphens or underscores (`advanced-stem`), never a space — because it travels as a URL path, a `--track=` argument, an `id` suffix and a `data-*` value; the name a person reads is the `label`, which is free to carry spaces, accents and an arrow (`English → Basic Portuguese`), so nothing about the display ever forces a rename. **A folder name is chosen once**: the teacher's access sheet stores the track name itself, so renaming a folder orphans every grant that mentions it (a hyphen is safe everywhere; a space is not); root tracks.json and lessons.json are generated from those folders by build-lessons.mjs and are never hand-edited. A folder holding ONLY track.json is a valid track: it is listed and grantable before its first lesson exists, and the QA sweeps skip it because it has no pages
— backend/Code.gs — qa/landing.mjs (index.html / student index structure, jsdom) — qa/content.mjs (structure) — qa/overflow.mjs (layout, real Chrome) — qa/games4.mjs (engine4.js / the game runner's state machine, jsdom) — qa/live.mjs (real-Chrome CDP harness, run with `node qa/live.mjs`) — qa/track.mjs (the one place a harness learns its SCOPE: the track list is DISCOVERED from the folders — no `--track` = every track that has pages, `--track=<any track folder>` narrows it) — qa/off.mjs (the kill switch: every harness on this line except qa/liquid.mjs prints one line and exits 0 unless `QA_ON=1` is set — owner instruction 2026-11-10, ISSUES.md) — qa/lang.mjs (the one check a build runs on its own page: the page's own voice against [PORTUGUESE]'s band) — node_modules/ (untracked, gitignored)
