# CONTENT_EXAMPLES — A menu of **mechanisms** and skins for content authored in the page's HTML

## [BUILD] - Ignore this section for lesson generation

### [GAMES]
1. There is **no house style**. Look, palette, motion and mood are chosen per game.
2. **The page must still work if the engine never loads.** The authored `.qitem`s are ordinary radios: they render, save and print with no JS. That fallback is not optional.
3. **No network at run time.** Art is CSS, inline SVG, or a local file. Nothing fetched from another host, so a page that ships today still renders in two years.
4. **Fits its slot.** A vehicle or stage has a defined .itemsize or range of .itemsizes with which it is compatible and never overflows.
5. **Reduced motion is honoured** — `prefers-reduced-motion` removes travel and keeps the state change, so the game still tells the student what happened.
6. **Cheap frames.** Animate `transform` and `opacity`; avoid animating layout properties, which jank on a school laptop.
7. **Difficulty and content are data.** Every game reads its items from the page and its knobs from `data-*` attributes, so a teacher can add items or change difficulty without editing an engine.
8. **The content in the page.** Games drive authored `.qitem`s (stem + optional `.listen` + radios), `input.gap`, or a textarea — nothing else. Whatever the engine animates is presentation; the saved answer is always one of those controls. If a mechanism cannot end in one, it is not a vehicle, it is a decoration. 
    
### [BLOCKS]
- **A figure is optional.** The cheapest visual for a point inside a phrase is a class on the phrase, not a picture, and a picture that only repeats the sentence is worse than the sentence. Draw when the point is *where something is* or *how something moves*.
- **If the beat is scored, a control saves it.** `.qitem` radios, `input.gap` and an authored `textarea` are what the engine records; a slider, a hotspot, a hover-reveal or a `<details>` looks interactive and records nothing. A figure may illustrate an item and never stands in for the control — and an item with no figure at all is the normal case.
- **CSS is fair game.** `style.css` for anything a lesson page will use, `qa/preview-visual.css` while a shape is still a draft. A new **top-level block** class must be added to `qa/overflow.mjs`'s selector list or it is never width-checked; an inline span needs no entry, because it cannot widen a block.
- **Where a label lives is per figure.** An HTML label reflows, wraps at any width and is announced by a screen reader; an SVG `<text>` stays at a fixed point in the drawing but cannot wrap and is read out of order. Prose-length labels go in HTML beside the figure; a one-word mark that must sit *at* a point (a gap, a `1`) may live inside the drawing.
- **Every shape here is prototyped as real markup** in `qa/preview-blocks.html`, under its own `<section class="qa-item" id="item-NN">`, so a build copies a working thing rather than a description of one.

### [VISUALS]
- **Depth, in this order of importance.** **Occlusion** first — the near face painted over what is inside, so a ball in an open tin loses its bottom while a ball on the closed lid keeps its whole circle: this is the cue that separates *in* from *on*. Then **the opening** — an ellipse filled dark says you are looking into something, without a single perspective line. Then **a contact shadow** — an ellipse the object sits on, not a circle floating in space. The primitives are `.lid`, `.side`, `.cav`, `.shadow`, `.screen`, and every figure that needs depth draws its near face **last** for exactly that reason.
- **Flat on purpose** where depth would add noise: an abstract diagram (a decision tree, a single time axis, a gauge) and a true sagittal section, which is a genuinely 2-D object.
- **Inline marks — the phrase is the figure.** Most of what a lesson shows about pronunciation is a property of one or two letters inside a sentence: which syllable is loud, where the tune turns, which sound joins the next word, which letter is written and not said. That needs a `<span>` with a class and no figure at all — it fits a full panel and a `.third` column without a width decision, prints black and white, cannot overflow, stays glued to the word if the sentence is edited, and is the only visual that survives a screen reader with its meaning intact. All of it `.mk-*`, all of it due in `style.css`:

| class | draws | suits |
|---|---|---|
| `.mk-stress` | a filled dot above the syllable | stress placement, `RE-cord` against `re-CORD` |
| `.mk-rise` / `.mk-fall` | a small ↗ or ↘ at the point of the turn | intonation, statement against question |
| `.mk-link` | a dotted tie between two words | connected speech, `an_apple`, `go_on` |
| `.mk-drop` | a struck letter | a letter written and not said, `Wed(d)nesday`, `(h)our` |
| `.mk-syl` | a thin rule between syllables | syllable counting, `com|pu|ter` |
| `.mk-pair` | a highlight with an underline | the two letters that differ, `s(i)t` / `s(ea)t` |
| `.mk-slow` | opened letter-spacing | a sound held longer, `so(oo)n` |

- **The shape carries the meaning; colour only reinforces it.** A dot, an arrow, a tie, a strike and a rule are five different shapes, so a grey print, a projector or a red/green confusion still reads all five. `posMarks` adds the same rule to underlines: the line style separates the classes and the colour reinforces it.
- **The mark never replaces the control.** A marked sentence is still an item: `.qitem` radios whose stem carries the marks, or an `input.gap` sitting inside the phrase, which is the same insight as the mark. Display alone records nothing.
- Authoring is one span at the point of the mark, empty where the mark is the whole content:
```html
<p>I <span class="mk-stress">RE</span>cord it, then we
   <span class="mk-pair">s</span>it on the <span class="mk-pair">s</span>eat<span class="mk-rise"></span></p>
```
- **The element-as-plate list** — where the element itself is the teaching device, the element *is* the plate and needs no class: `ruby`/`rt` (a key over a word), `figure`/`figcaption` (a picture and its line), `<s>` (a rejected line, an erasure), inline `<svg>` (a drawn map, timeline, mouth), `<img>` from `assets/` (a photograph, sign or form). An image is always a local file (`[GAMES] 3`), and a vehicle whose `markup` uses any of these names the ones it uses.
- **Outside art: vendored, never hotlinked** (`[GAMES] 3`), so an outside picture means downloading the file into this repo, with provenance and licence in `assets/README.md`, referenced as `../assets/<name>.<ext>` and captioned with its source on the page that uses it. **The licence travels with the file** — a share-alike plate means a recoloured or highlighted derivative carries the same licence. And **a real anatomical plate teaches anatomy, not articulation**: nothing licensed shows where *this* student's tongue must go, so the arrow, the highlighted path and the Portuguese instruction line do that; draw the schematic and use outside art as the accuracy reference.
	
## [INSTRUCTIONS] for selection and implementation
- **A menu, not a checklist.** Nothing here is required in any lesson or in any order; a vehicle is used when it is the optimal way to present content the build already has.
- **Shape is the vehicle's use, in four atoms** joined by `|`. A combination means exactly the union of its parts and carries no definition of its own.
	- `TEACH` -> Explains, elaborates , gives translations, or otherwise passes understanding or knowledge to the student.
	- `TRAIN` -> Any activity that makes the student utilize their knowledge.
	- `SHOW` -> Presents or demonstrates but does not 'teach' - must be combined with another vehicle that [explains or uses] it as a [teaching or training] example, which is why it is never a shape on its own.
	- `OPTION` -> The block declares, in its **markup**, a designated slot *inside its own container* — the same `.panel` or `.card` — that may hold any one content type, or another vehicle's markup. The slot never becomes a container of its own.
- **Headings are the index.** Every `### ` heading reads `[NN] <shape> <itemsize> <what it is and/or does> <items> <options>`. `itemsize` is the block's default width as the stylesheet names it (`full`, `half`, `twothird`, `third`, `half->`, `third->`). In the counts, omit either number when it does not apply — `<3|>` is three or more with no ceiling, `<|4>` at most four — and write `< , >` when neither applies. The phrase is in the third person, naming **wha	t the vehicle does** and/or what the **student** does("the student ranks…", "…a box the student fills"), never left implied by an imperative, which reads equally as a build instruction and as a task. `node qa/brief.mjs` prints this index; the lines under a heading are read only **after** a shape is chosen (`qa/brief.mjs --section=NN` prints one).
- **The tone of a lesson comes from the lesson's copy, never from here.** Every vehicle is track-neutral.
- **`<h3>` and `<h4>`.** `<h3>` begins with a letter by its order in the section, and is followed by the text the vehicle's **markup** defines it to be — or, where markup defines none, a super-minimal phrase that names the block's function or contents, never filler. `<h4>` is mandatory when the vehicle's **markup** defines one, and otherwise an optional one-line explainer of the contents that never restates `<h3>`. **A block's introduction or explainer is an `<h4>` and never a `<p>`**: `<p>` inside a block always carries the block's own content, so the element alone says whether a line introduces the block or *is* the material.
- **The saved answer is always a control** (`[BLOCKS] 2`): `.qitem` radios, `input.gap` or a `textarea`. A figure, a mark, a fold or a highlight shows; it never scores, and an entry that cannot end in one of the three is not a vehicle.
- **A figure with no item of its own is not a vehicle.** Where a drawing, a mark or a highlight has nothing that saves, the *host* block owns the container and the control and the figure is drawn inside it — `[INSIDE]` lists those five, and it is the whole of that list. Such an entry carries `< , >` for both counts, is never chosen on its own, and is written to be dropped into a block that already exists.

### [02] <TEACH|OPTION> <THIRD-> Plays a recording with lyrics and shows which line is being sung < , > < , >
- **markup**: a `.panel`; `<h3>` = the song's own title, never the vehicle's name; **`<h4>` = who performs it, and nothing else, italic because every `<h4>` is** — it is the block's credit line, and it is the last thing above the player. Inside: `figure.vz-play` with **no `figcaption`**, so nothing is printed above the `<audio>`; `<audio class="vz-audio" src="../assets/<name>.mp3" data-duration="<decoded length>" controls preload="metadata">`, `data-duration` being the length measured at authoring time, which the bar, the clock and `End` use (a browser's own `duration` for a VBR file is an estimate); the drawn controls — a `.vz-btn`, two `.vz-time` readouts, a `.vz-bar` with `.vz-fill` and `.vz-knob`, the bar `role="slider"` with `aria-valuenow`; `<ol class="vz-lyrics">`, one `<li>` per line, `data-t` in seconds on any line whose time is known. The native `controls` attribute is the floor: with no JavaScript the student still plays, pauses and scrubs, and `qa/player.js` removes it only after wiring the drawn bar, the keyboard (`←`/`→` five seconds, `Home`/`End`), click-a-line-to-seek and the lyric highlight. `data-kind="teach"`, no `data-move`, no `load` — nothing is scored. At full width the same figure carries lines too long to hold at a half and the highlight still falls on one `<li>`. One optional `<p>` under the `<ol>` — content, not an introduction, so it is a paragraph and not an `<h4>` — one paragraph explaining the words and never the block, present only when the point is inside the words. **The `OPTION` slot sits inside this same `.panel`**: one `<h4>` naming what it holds, then any one content type — a `.chart`, an item list, a paragraph — omitted when the lesson has nothing to put in it, and never a `.panel` of its own.
- **source**: one command, run by the build and pasted as printed: `node qa/audio.mjs --file="File:<name>.ogg" --lyrics="line|line|line" --out=<name>`
  (`--width=full` prints the full-width shape of [03] and is omitted for [02]; `--times=a,b,c` when the file ships its own
  timed transcript; `--from=<s>` when it opens on a spoken intro; `--title=` / `--credit=` when the file name and the
  Commons metadata do not give the song's title and its performer). In order: (1) reads the licence from the Commons API and
  records it for the provenance row — **no licence is refused**; (2) refuses a description that names an instrument and no voice,
  unless `--times` is given; (3) downloads Wikimedia's MP3 transcode; (4) decodes it into 20 ms RMS windows — a silence is
  240 ms or longer under max(2% of peak, 0.002), the sound between two silences is a phrase, and anything under 0.3 s is
  breath; (5) refuses the timing unless the phrases are 1.2–22 s, within 3.2× of each other, and at least as many as the
  lyrics; (6) takes the line starts from the phrase starts, or from the cues with `--times`, rebased to the cut, and cuts
  0.05 s before the next phrase start or the next cue, or at the end of the file when there is no next one; (7) copies the
  frames without re-encoding and rewrites the cut's `Xing`/`Info` frame — frame count, byte count, 100-entry seek table;
  (8) decodes the cut and prints its length, which is `data-duration`; (9) proves every `data-t` by energy, 0.5 s after it
  (`t+0.1`–`t+0.6`) against 0.25 s before (`t−0.35`–`t−0.1`): a derived start is more than 1.5× the before-window and at
  least 0.004, a transcript start at least 0.006, and a failure stops the run; (10) prints the panel, the figure with its
  lyric list, and the provenance row for `assets/README.md`.

### [04] <TEACH> <THIRD-> Presents a word's etymology and how that is relevant or useful to the student <2|4> < , >
- **markup**: one `.panel`; `<h3>` = **the word being presented**, its first letter capitalised (`Nice`) and never the vehicle's name; a `dl` — a `<dt>` per stop carrying the date and the language, a `<dd>` under it carrying the definition (the form and what it meant then) and, **on the line below that definition**, after a `<br>`, the one-line description of what happened to the word at that stop (`the word enters meaning foolish`) — because a list of stops is a definition list, and a table would rule the journey into separate boxes; one `.dim` line at the end carries the payoff ("the spelling froze around 1400; the sound kept moving"), the sentence the student should leave with. `data-kind="teach"`, no `data-move`.
- **info**: it is used only once the lesson has made the word strange, it explains present oddity and never present usage, and every date and form is checked — a made-up etymology is an error the student keeps for life. Its relevance is the payoff line's job: an etymology that is merely interesting is a fact the lesson paid a block for and cannot use, so the line says what it is for now.

### [05] <TRAIN> <HALF-> A drawn street map with numbered places to route through <4|5> <2|4>
- **markup**: one `.panel`; an inline `<svg>` street map (element-as-plate: inline `<svg>`, `<img>` from `assets/`) with no depth and no art but enough of a town to route through — two high streets crossed by two side streets, the streets named in small text, each place **drawn as the thing it is** — a platform building under a canopy with a clock on the wall for the station, a striped awning and a cup for the café, grass and two trees for the park, a pediment over four columns for the bank, a wall of book spines for the library, a postbox and an envelope over the door for the post office, a shelter on two posts with a bench for the bus stop, two awnings with stripes for the market — each drawing carrying one feature that names it, because eight identical rectangles named only by their labels are a diagram of the list under them and not a street the student can walk; each place's **checkbox sits on the drawing** — a `<label><input type="checkbox" aria-label="the station"> 1</label>` inside a `position:absolute` box over that place, the `<svg>` wrapped in a `position:relative` one and each box's `left`/`top` given in `%` of the drawing — because ticking a place as it is passed is what turns a route into a sequence, and a row of checkboxes under the picture is a second thing to read that is no longer on the map; then one `input.gap` per leg at `--gap-w:100%`, each naming its two ends by number and name ("from the station to the post office: …"); one `.dim` line limiting the student to the place and street names on the map. An `<img>` from `assets/` is allowed where a real map is the material, and is never remote. `data-kind="train"`, `data-move="produce"`.
- **info**: the map is legible at half width, or the block is a full-width figure; a drawing that could be any building leaves the student naming the place from its label after all, so each one carries the feature that identifies it; and the place names close the alternatives, since a route with more than one reasonable answer needs both accepted.

### [06] <TEACH> <HALF-> Cue, the form it forces, an example <4|6> <3|3>
- **markup**: a `.panel` whose content is one `.chart`, three columns (`<cue>` · `<what it forces>` · `<example>`), four to six rows, column one pinned at about 12% by a `<colgroup>` and headed `The Cue`. The cue is always the shortest cell in its row, so every pixel it does not take is a pixel the example gets, and the examples can then be full sentences at a half width. The table is the whole display — no `tr.note` under it: the row that used to name the one cue that is a trap is not in this shape, so a cue that only mostly forces its form is corrected in the item that tests it. `data-kind="teach"`, no `data-move`.
- **info**: no cue is decisive on its own, and a table that reads "always" when the language only mostly does this teaches a false rule.

### [07] <TEACH> <FULL> One contrast across three word positions <2|4> <3|3>
- **markup**: one `.chart` whose first column is the written form and whose other columns are the positions (start, middle, end), each cell a word with its own `.listen` chip. Where a written form belongs to Portuguese rather than to English — `x`, `ti`, `ão` — the marker carries **both** `class="pt"` and `lang="pt"`, so it is italic and in the Portuguese colour: the reader sees at a glance that the row is their first language, and no cell ever says so in parentheses. `data-kind="teach"`, no `data-move`.
- **info**: it is listening and mouth-work only, it never hands the student a phonetic symbol this project does not use, and a grid with more than two sounds per row stops being a contrast and becomes a catalogue.

### [08] <TEACH> <HALF-> Two word sets as rows and columns, ticks where they combine <3|5> <3|4>
- **markup**: a `.panel.itemsize-half` whose content is one `.chart.center`: `<set A>` down the side, `<set B>` across the top, `✓` and `✗` in the cells. The article belongs with the verb, not with the noun — rows read `make a` · `take a` · `do a`, heads read `photo` · `shower` · `decision` — so a column of `a`s is not repeated down the table and the row is the thing that can be said. Column heads are set 2pt below body size, since they are labels over a grid rather than text to read, and the whole chart is centred because a tick matrix is a picture, not a paragraph. `data-kind="teach"`, no `data-move`.
- **info**: ticks are not explanations — where a combination is blocked for a reason rather than by convention, the matrix hides it and the reason belongs in a rule card beside it.

### [09] <TEACH|TRAIN> <HALF> Pairs an everyday verb with its one-word twin, then asks which twin fits <3|6> <1|1>
- **markup**: two half-width blocks. The first is a `.chart` with the twin in the left column and the everyday form filled in the right — the source list, `data-kind="teach"`, no `data-move`. The second is **four long phrases, each with the gap inside it**: a sentence long enough to say *when* the form would be used (the deadline nobody wanted, the neighbour, the payment nobody chased), an `input.gap` of `--gap-w:8em` sitting at the point the form belongs in, and one instruction line naming the block above as the source — no letter bank beneath, because the forms are the other block's right column and a second copy of them turns the item into a copying exercise. `data-kind="train"`, `data-move="produce"`. Not checkboxes: a written form is what the student will have to say, and a row of ticked boxes records nothing they can read back.
- **info**: the pairing is genuinely interchangeable, or the chart teaches a false equation; and this is a vocabulary lesson, not a meaning lesson — the student learns the register of a word they already understand.

### [10] <TEACH|TRAIN> <HALF> Two correct versions of one message for a named hearer <3|6> <2|4>
- **markup**: two `.panel.itemsize` blocks — the stiff/loose `.chart` (`data-kind="teach"`), then the audience task that uses it (`data-kind="train"`, `data-move="choose"`). The merged `tr.note` row — one line held up as both registers at once — is **an option, never a default**: it is included only when the lesson's point is that a sentence can be unstuck from its audience, and a build that always emits it is teaching that two registers are one. `data-kind="teach|train"`.
- **info**: every item names its audience, or the item is unjudgeable; both wordings are ones people really say or write — a softened form invented for a phrase that never needs softening teaches a register the student will never meet, and if one of the two forms is not genuinely in use the contrast is not a contrast; and it only ever chooses between wordings someone else wrote, never produces one.

### [11] <TEACH|TRAIN> <HALF> One root's forms in columns by the job each does <5|5> <3|6>
- **markup**: a five-column `.chart` for the family itself (verb · person · thing · **thing2** · description, `data-kind="teach"`), then an item list of sentences with one `input.gap` each, deliberately including one sentence where the student's first instinct is the wrong member (`data-kind="train"`, `data-move="produce"`). `thing2` earns its column because it is where the words that are neither the object nor a person land (`production`, `explainer`), and leaving it out pushes them into a cell that is already wrong. `data-kind="teach|train"`.
- **info**: only works on roots that really do have distinct members in use — inventing `<root>ness` to fill the grid teaches a word nobody says, and the student will use it confidently.

### [12] <TEACH|TRAIN> <FULL> 'Unknown plan' block, beside block with fields to have the student ask questions and learn the details that they need <1|1> <4|8>
- **markup**: two panels on one row — the facts in a **third** and the questions in **two thirds**, so the unknowns and the fields that answer them stay in view together. **B's `<h3>` is the instruction itself** — `Ask questions to clarify the plan:` — because a block that needs something from the other student should say so in the one place a student's eye lands; its body is then only the form with its gaps, and there is no further caption. A's header names what A holds. Neither block carries a `tr.note`: the exchange is the block. A is `data-kind="teach"`; B is `data-kind="train"`, `data-move="produce"`. `data-kind="teach|train"`.
- **info**: everything is answerable from the page, so it is a written information gap and not a speaking one; and a half that already contains the other half's answers kills it.

### [13] <TEACH|TRAIN> <HALF> A real document read for what its parts do <1|1> <3|>
- **markup**: a half-width `.panel` whose content is one `.chart` (`data-kind="teach"`), with a `<colgroup>` that **pins columns 1 and 3 to their content** (`width:1%` with `white-space:nowrap`) and lets the middle column take the rest: the label and the fixed words are short and predictable, the free text is not, so the free column is the only one that should stretch. A `<tr class="note">` may carry the one convention that no column header can. Then the item grid that asks where in it, also at half width — `data-kind="train"`, `data-move="spot"`. `data-kind="teach|train"`.
- **info**: it cannot test production; the authoring cost is the real one — an invented artefact teaches a convention that does not exist; and the lesson names what the artefact is for, or the questions are guesswork.

### [14] <TEACH|TRAIN> <HALF> Notices, the options each offers, the word doing the work <4|8> <4|4>
- **markup**: **one block only**, the chart: a `<tr class="note">` naming the sign, then four rows whose second column holds the same four options **in the same order down every row** — a column whose order changes row by row is a second puzzle laid over the first. Radios are grouped per row, so one choice is recorded per sign. `data-kind="train"`, `data-move="choose"`.
