# CLINE COURSE AUTHORING WORKFLOW

## File Path & Naming Conventions
- **Root Shell Template:** `_shell.html` (in workspace root)
- **Track Root:** `<track>/` (in workspace root, where `<track>` is `kids`, `business`, or `adult`)
- **Roadmap:** `<track>/roadmap.md`
- **State Ledger:** `<track>/track_ledger.json`
- **Target Lesson HTML:** `<track>/lessons/lesson_<NN>.html` (zero-padded to 2 digits, e.g., `lesson_01.html`, `lesson_12.html` — adjust if your existing files use non-padded numbers)

## Strict File-Access Boundary (ZERO EXPLORATION)
- **ONLY read the exact 5 files listed in Step 1 + `_shell.html` + the target lesson HTML file.**
- **NEVER** read, search for, glob, or open `.css` files, `.js` files, `lessons.json`, sibling lesson `.html` files, or any legacy/unrelated files in the repository. Do NOT inspect CSS classes or styling.
- **DO NOT** build full game players, audio players, or SVG maps. Leave clean placeholder directives (`<!-- TRAIN_HERE -->`, `<!-- QUIZ_HERE -->`, `<!-- MUSIC_HERE -->`, `<!-- MAP_HERE -->`) with raw content/questions so the downstream build pipeline can fetch assets, skin the widgets, and finalize formatting.

## Track Placeholder Mappings
When populating `_shell.html` placeholders, use these exact values per track:
- `kids` -> `{{TRACK_TITLE}}`: `Kids`, `{{TRACK_UPPER}}`: `KIDS`
- `business` -> `{{TRACK_TITLE}}`: `Business`, `{{TRACK_UPPER}}`: `BUSINESS`
- `adult` -> `{{TRACK_TITLE}}`: `Adult`, `{{TRACK_UPPER}}`: `ADULT`
- `{{L}}`: Lesson number (unpadded integer, e.g., `1`, `12`)
- `{{LESSON_TITLE}}`: **Generate this title yourself** based on the lesson's topic/concepts in `<track>/roadmap.md` and the register/voice of `<track>` (punchy/playful for `kids`, sharp/practical for `business`, candid/street-smart for `adult`). Do NOT look up titles in external files.

## Execution Pipeline (Run Automatically on Every Lesson Request)

Whenever asked to write, draft, or update a lesson (e.g., *"Write Lesson 22 for adult"* or *"Write the next lesson for kids"*):

### 1. Resolve Target & Load Pedagogical Context
- Read ONLY these 5 files:
  1. `<track>/track_ledger.json`
  2. `<track>/roadmap.md`
  3. `Prompts/01_pedagogical_core.md`
  4. `Prompts/02_track_voices.md` `<TRACK>` section ONLY
  5. `Prompts/03_interactive_blocks.md`
- If no lesson number was specified in the user prompt, use `current_lesson` from `<track>/track_ledger.json`.
- `unlocked_lemmas` is what the course has already taught: use those words freely, review them, build on them, but never teach them again as new material. The lesson's `Vocabulary:` line in the roadmap is the plan, not a limit - teach the words the lesson actually needs, and record them in step 4.
- `lessons` holds the words each lesson added, keyed by lesson number, so the recent end of the course is visible. Bring words -as they fit naturally - from the most recent entries back into later English prose and example sentences, in new contexts, so the student meets them again - exposure only: never re-explain, re-define, gloss or drill them. Where `lessons` has no entries yet, `unlocked_lemmas` is the record.

### 2. Initialize Shell & Replace Placeholders
- Check if `<track>/lessons/lesson_<NN>.html` exists.
- If it does **not** exist, create `<track>/lessons/` if needed and copy `_shell.html` from the workspace root to `<track>/lessons/lesson_<NN>.html`.
- Generate a fitting, track-appropriate `{{LESSON_TITLE}}` from the roadmap entry for Lesson `{{L}}`, then replace `{{TRACK_TITLE}}`, `{{TRACK_UPPER}}`, `{{L}}`, and `{{LESSON_TITLE}}` in `<track>/lessons/lesson_<NN>.html`.

### 3. Author Lesson Content Directly into Shell HTML
- Locate the main `<h1>` tag in `<track>/lessons/lesson_<NN>.html` (after replacing `{{LESSON_TITLE}}`) and insert all authored lesson content immediately below the closing `</h1>` tag.
- **Split by high-level concept, not by what you can name.** One section is the default: Split only where the split earns its place in clarity. Meaning, formation and contraction are aspects of one ability, not three sections: teach *to be* as one thing he can use, and let am/is/are and I'm/he's sit inside it - Section divisions are conceptual, block divisions are organizational.
- Strictly follow all teaching rules in `Prompts/01_pedagogical_core.md` (rule-engines over memorization, tense-carrying auxiliaries, distractor quarantine, mandatory contractions, keys pasted from `PRONPARSE.md`, and clause-by-clause bilingual code-switching).
- **Enforce Logarithmic Bilingual Gradient & Headings (Semantic Coherence Rule):**
  - **Keep Phonetics & Deep L1 Traps in Portuguese:** Do not use your own phonetic spellings - (`PRONPARSE.md` keys, *flap T*, mouth mechanics) or nuanced Brazilian Portuguese contrast traps—keep those 100% in natural Portuguese.
  - **Portuguese is always marked:** every run of Portuguese text sits in `<span lang="pt">…</span>` - spans only, never a block, and the span covers Portuguese words only. English is never written inside it: when you rewrite a sentence, close the span around the Portuguese that remains and leave the English outside. The look is automatic (italic, ochre) - no class, no other attribute.
  - **Convert Logic, Rules & Transitions in Place:** Hit the lesson's minimum English ratio (`4%` L2–7, `10%` L8–14, `16%` L15–22, `35%` L23–32, `60%` L33–40, `80%+` L41+) by writing **structural rule explanations, cause-and-effect logic, and section transitions** in complete, sensible English (using ONLY `unlocked_lemmas` + transparent cognates).
  - **Never Use Filler or Broken Fragments. Never use figurative speech to explain a concept:** Every English heading (`<h2>`/`<h3>`) must be a complete, grammatical phrase (e.g., *"How It Sounds in Fast Speech"*). Never paste in example sentences just to raise the English word count.
- **The training is yours:** pedagogical choices belong to this pass, never to the renderer. For each section decide what must become *automatic* and what the student will say instead, then write the activity where it trains that - inline under the section it teaches, or in a closing practice section when the lesson wants one.
  - Why a thing is trained is one of four: **difficulty** (rare or irregular - examples are enough, do not drill it), **selection** (two known forms compete and the right one must come out without a pause), **interference** (Portuguese offers a form English does not), **chunk** (it must leave the mouth assembled - contractions, *get up*, *I'd rather*). *To be* is selection, interference and chunk - not difficulty.
  - Write each activity as a directive with its stems **and their answers**, placed where the activity belongs:
    `<!-- TRAIN_HERE: type=fill | why=selection`
    `Q1: I ___ from Brazil. | am`
    `Q2: She ___ tired. | is`
    `-->`
    `type` is what the student must do, and nothing else: `mc` (one right answer among the wrong ones — a word, a form, a meaning or a fact), `fill` (typing the exact form into the sentence), `matching` (pairing each item with its meaning from one shared pool), `chunks` (rebuilding a sentence from its pieces), `correction` (finding the one wrong word and writing the sentence again), `translation` (Portuguese into the English the lesson taught, or back), `dictation` (hearing a sentence once and writing it down). Every type carries its stems **with their answers**; what an answer looks like is the type's business. `why` is one of the four words above. Never name a game: a game is a skin over an activity, never a type, and the renderer reskins an activity as a game where one fits.
  - Difficulty is the student's, not yours: an early lesson trains few things slowly, a late one trains many and fast, and an item that needs vocabulary this lesson has not taught is a bad item at any level.
- Match the explainer register and target English style defined for `<track>` in `Prompts/02_track_voices.md`.
- Follow `Prompts/03_interactive_blocks.md`:
  - You **MUST** make the training thorough: a `TRAIN_HERE` wherever a section's training ends, a `DIALOG_HERE` where a conversation carries the section, and a `QUIZ_HERE` at the lesson's end when the lesson wants one. There is no count and no quota, and no lesson owes a game — the student should be comfortable and well-practiced with the lesson concepts and vocabulary when they finish.
  - Whenever referencing a song, you **MUST** name the real song/artist, quote the exact target lyrics with a `PRONPARSE.md` key over the reduced words, and insert a `<!-- MUSIC_HERE -->` directive block (never write vague prose teasers). If no usable recording turns up, the block still ships: the player is swapped for a link carrying the quoted line's start time, the lyrics are written out with no `data-t`, and the credit line says where the song came from — never drop the block and never invent a recording.
- Explicitly connect new material to what earlier lessons already taught (the roadmap's earlier lessons and `unlocked_lemmas`) where relevant.

### 4. Record the Vocabulary
- Before the audit, write the English words this lesson actually teaches into `<track>/track_ledger.json`: record them under `lessons` keyed by the lesson number you are writing (`"51": ["harbor", "pier"]`), and increment `current_lesson` by `1` so the next request picks up the following lesson.
- The ledger holds `track`, `current_lesson`, `unlocked_lemmas` and `lessons`, and nothing else.

### 5. Run Deterministic Audit (Mandatory Loop)
- Execute in terminal, passing the lesson number because `current_lesson` has already moved on:
  `python scripts/audit_draft.py <track>/lessons/lesson_<NN>.html <track>/track_ledger.json <NN>`
- The audit separates the languages by markup alone: text inside `lang="pt"` is Portuguese, everything else is English. It reports the English headings, the English prose ratio and the structural directives.
- If `audit_draft.py` exits with an error (`FAIL` on missing `MUSIC_HERE`, insufficient English headings, `English prose ratio below minimum`):
  - Fix the exact issue reported in `<track>/lessons/lesson_<NN>.html`:
    - If English sits inside a `lang="pt"` span it is counted as Portuguese - close the span around the Portuguese words and leave the English outside it.
    - If `en_ratio` is too low, convert additional straightforward Portuguese rule sentences **in place** inside existing paragraphs (leaving pronunciation/L1-trap paragraphs in Portuguese).
  - Re-run `audit_draft.py` until it exits cleanly with `PASS`.
- If the audit changed which words the lesson teaches, correct `unlocked_lemmas` before finishing.
