## GOALS
- "Inglês Abre Portas": a static English-teaching site — one teacher plus a few allow-listed students, three books (kids, business, adults/nsfw); every lesson is a standalone page.
- A student reads/listens to a lesson and marks it up (highlight, note, record); every mark persists server-side per student and per book, and the teacher sees the same layer (student selector in the control bar).
- Non-goals: no client-side source of truth (the server is the sole source); the only client-side access list is the teachers in access.json.

## ARCHITECTURE
- Pages: login (index.html) signs in with Google, checks the server-side access status, and hands a signed `sessionStorage.gate` to `<track>/lessonN.html`. An unrecognized account submits a pending request; the teacher area (shown to a teacher after login) approves or rejects each request and assigns the student's book at approval.
- Lesson pages are content-only: config consts (BACKPACK exec URL, SECRET, TRACK, L, COUNT) + `<script src="../engine1.js">` + `<script src="../engine2.js">` + style.css.
- engine1.js = gate, gestures/selection popup, notes/recordings/audio, highlights, network-last writes. engine2.js = control bar, adaptive layer poll (1s active / 5s idle / paused when hidden), feed, restoring saved marks.
- **Teacher edit-mode content is SERVER-SIDE, not in the local files.** The browser ✏️ Edit auto-saves the WHOLE page as a sheet row — `type:"content"`, `id:"content_<track>_<lesson>"`, the teacher's `email`, and the full-page HTML in `data` (control bar and feed emptied). To retrieve it (e.g. for an "I edited lesson X — update / integrate / bake in" prompt): `GET <BACKPACK>?action=layer&email=<teacher email>&lesson=<n>` → JSON `{rows:[…]}`; take the `type:"content"` row's `data`. DEFAULT = FULL OVERWRITE: write that `data` over the lesson file and re-copy the `<lesson>.edit.html` sidecar. Any narrower scope (e.g. one section only, or just the `.content-area` innerHTML — which lives inside `data`, outside `<html>/<head>/<body>/<header>/<script>`) happens only when the owner explicitly asks.
- One server (backend/Code.gs — see BACKEND.md): Sheet `IAP_backpack!layer` + Drive folder `IAP_uploads`. It is the ONLY source of truth; a local action is shielded from a racing poll by a generic id+action grace window (12s).
- Three mark families that must never interact: notes (a light blue wash), recordings (a blue underline) and highlights (translucent coloured rectangles) — each painted on its own visual layer, so overlapping marks never conflict.
- ANCHORING (owner spec 2026-10-13, binding): the lesson content is ABSOLUTE, FIXED CONTENT — a published lesson page's prose never changes and never moves (and no styling may shift, resize or reflow it either — a mark is a visual OVERLAY drawn without touching the content's box model; an underline/wash inset is a background draw, never padding/margin on the content itself). Every persisted item consequently references a TEXT STRING as its anchor: highlights, notes and recordings are stored, matched, painted and restored by their anchor text (plus the note text / colour / clip they carry). Position is NOT the reference — it is only allowed as a TIE-BREAKER to discriminate when the same anchor string occurs more than once on a page (which occurrence / place the item belongs to). So a repeat of the same phrase is resolved by the position stored with the row, and the rule is: text identifies the item, position only picks between identical candidates — never the other way round.

## VERIFICATION ENVIRONMENT
- Playwright is unavailable here, so `qa/smoke.mjs` runs on jsdom: JS syntax, DOM structure, engine init flags (`__A`/`__B`), the selection popup, the highlight Ctrl gesture gate, `#hlLayer` paint separation, the colour palette, Ctrl+click delete and the layer-independence rule. jsdom has no layout, so the suite installs a deterministic fake layout (8px/char, 40 chars/line, 20px/line) to exercise rectangle geometry and the hit test — it does NOT cover real rendering, media, or actual mouse/keyboard events.
- Real input/timing bugs (e.g. the 2026-10-12 palette that the held Ctrl's auto-repeat killed) CANNOT be caught by jsdom — QA stayed green while the live page was broken. When a report mentions timing, auto-repeat, real mouse/keyboard or on-screen position, drive a real headless Chrome over the DevTools Protocol (throwaway probe: `--headless=new --remote-debugging-port=0`, `Input.dispatchMouseEvent`/`Input.dispatchKeyEvent`, `Runtime.evaluate` to read `getBoundingClientRect`) instead of trusting the jsdom suite alone. That harness now exists and is tracked: `qa/live.mjs` (real Chrome over CDP, zero npm dependencies).
- QA is scoped to what changed (HARNESS RULE 4): `qa/content.mjs` (structure) and `qa/overflow.mjs` (layout) accept one or more lesson numbers — `node qa/content.mjs 5`, `node qa/overflow.mjs 5` — and sweep 1–34 only when run with no numbers.
- `raw.githubusercontent.com` caches branch-name fetches briefly — verify fetched content by commit SHA when in doubt.
