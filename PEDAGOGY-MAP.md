# [GENERATION] DO NOT MODIFY WITHOUT USER SIGN-OFF - **No other page is an input, and reading one is the act that is barred** — during a generation no `lesson<N>*.html` (any track, any lesson) and no `preview*.html` may be opened, searched, diffed, quoted, offered as precedent, or recalled from memory: not its content, not its markup, not its link line, not its class or attribute names, not its naming scheme, not its order. **Plumbing is not exempt** — the stylesheet a page links, the shell it was copied from, the scripts it loads, how a control is written, how an answer is keyed, what the file is called: each is answered by an input the list below allows, or it is a question for the owner. Each lesson generation starts fresh.

1. Generation **BEGINS** by copying `_shell.html` - The frame is fixed — head, `header.brand`, `#controlbar`, `#barhelp`, `main#page > .page-container > .content-area`, the script slot.
2. Choose a title that names the main thing the lesson teaches, in the plain words a student would use to describe it — never a slogan, a metaphor or a question — then RENAME the file to `lesson<N>-<Title>.html`: the filename carries the title, and it is the only place the site index learns either.
3. **[THE LOOP — one lesson at a time, in this order. A task may contain several lessons; the order never changes.]**
   a. **STEP 0, before every lesson — READ THE STATE.** `<TRACK>/BATCH-RECORD.md`, its last ten rows; `extra/lesson1-The Capability Map.html`'s index of occasions, its activity shapes and its **Learned during build generation** block; and the [CHECK] list below. Read them at the start of *every* lesson, never once at the start of the task: the ledger is the only memory of what has already been used, and a merged context is the normal case, not the exception. **There is no batch plan** — what this lesson must not repeat is read from what already happened, not decided in advance.
   b. **[PASS 1 — CONTENT, [1a] below]** Write the raw lesson — headings, explanations, examples, dialogs, activities with their instructions and keys, word lists, chart contents, song lines — **completely differently from the last lesson, before any formatting is applied**. The number of sections, their order, their shapes, the first block and the form its training takes are decided for this lesson alone, from what this lesson teaches. Of the map page, `extra/lesson1-The Capability Map.html`, it reads the index of occasions and the activity shapes — what a page *can* show, and what each shape is for — because 1A decides *that* a sentence is marked, or that the student picks between two forms rather than writing one, and never how either is built. It writes straight into `lesson<N>-<Title>.html`, and it writes the first half of the lesson's ledger row: every section's subject and device, every block's subject, and the quiz.
   c. **[PASS 2 — ARRANGEMENT, [1b] below]** Choose each element by the question it answers, copy its markup from the example `extra/lesson1-The Capability Map.html` draws for it, and let the rows 1A marked do the work — **flex flow is the default, and a width is written only to repair a cell the flow got wrong**. Set `data-look`. Run the tool the shape needs — `qa/pos.mjs`, `qa/audio.mjs`, `PronKey.render` — and paste what it prints. Finish with [1c]'s option-set layout. Then run the [CHECK] list against the page while it is still the thing being written, and append the second half of the ledger row: the elements it built, the quiz's elements, and the register score.
   d. **THE LESSON IS CLOSED.** Once its row is complete it is never opened again in this task — not to re-read it, not to compare it with the next one, not to quote it as precedent. It is reopened only by [ALIGN] (step 6), which may add an item, a block or a row to a cell that ends high, and by nothing else. The next lesson begins at (a).
4. The shell's placeholders are filled as the page is written — TRACK_TITLE and TRACK are the track's folder name as it is spelled on disk, TRACK_UPPER the same word in capitals. Nothing is read to learn them.
5. WHEN every lesson in the task is built, RUN `npm run mapcheck`, `npm run batchcheck` and `npm run build:lessons`. These are the batch's checks and they are mechanical: no page is re-read to run them, and a failure is repaired in its own lesson.
6. THEN the batch is ALIGNED and shipped: `npm run align -- --track=<track> --lessons=<range>` measures the rendered pages ([ALIGN] below), the short cells are repaired, the three checks run again, and the batch is committed and pushed. Alignment happens before the push because its instrument is the page, and by then the page is finished.

## [PASSES] — the three passes, in this order; the first pass decides nothing about form
### [1a] CONTENT — the raw lesson, before any shape
- **This lesson is imagined from scratch, and no part of its structure is inherited.** The number of sections, their order, their shapes, the first block, the form its training takes and every example are decided for this lesson alone, out of what this lesson teaches — never out of how the last page was built. A raw lesson that could be moved into another lesson's place by changing its words is a copy: rewrite it until its sequence is the one this content needs.
- **The page opens on the point it teaches.** The first teaching unit states what the student is about to learn; a scene, a dialog or a story is an example of content already stated and never the introduction. A page that opens on a conversation has shown the student something before telling them what it is for.
- **A section can contain multiple ideas, a block can contain multiple activities, teaching elements, rows of content, etc. Division without need is noise.**
- **The default number of teaching sections in a lesson should be 3. From 1 to 6 is totally acceptable with defensible utility, but more than that is probably an error rather than a good organization decision.** Every section past the third has one short teaching reason written on the lesson's ledger line (`sep:S4 - the song is the only place the two orders are heard`): the reason is about what the student must learn, never about layout, and "it looked long" is not a reason.
- **The whole lesson is written here, in full, in plain text.** Not an outline and not a plan: every explanation written out as the sentences the student will read, every example, every dialog, every activity with its instruction and every item in it with its answer, every word list, every chart's rows. A placeholder, a note to self, or a line saying what the section will later contain leaves the lesson unfinished — 1B builds what is written and cannot build what was only meant.
- **Every element the lesson uses is named with the details it needs to exist.** Not every lesson has a song or words to be spoken; whichever ones it uses are written out where they belong: a map and what it is for, a player and the song and line that relate to the lesson, a key and the words it sits above, a timeline and the phrase it is anchored to, a chart and the rows it holds, a dialog and who speaks each turn. The words that will be heard are written where they belong — the value that speaks them, the line quoted, the answer keyed — because that is lesson text and never something for 1B to invent.
- **A lesson about a tense draws the tense.** The word marks and the timeline are content, not decoration: the sentence is marked so the student can see which word has which function, and the line is drawn so they can see where *now* falls. A sentence the tagger mis-marks — the verb the lesson is about tagged as a noun — is rewritten until it marks the words the lesson is about; the marks are never dropped and never corrected by hand.
- **A song is considered here, and its section is planned here.** If a popular song contains the form the lesson teaches in one line, 1A writes that section — the line, what it shows, what the student predicts, the production that follows — and leaves the player for 1B, which cuts and times it.
- **Training trains the element it sits beside.** It may sit inline with that element or in a section of its own; its shape is chosen by what the student must do, and the shapes vary across the lesson — a lesson whose every activity is the same shape has not imagined its practice.
- **Every training block is justified in one sentence before its shape is used: what the student must produce, and why this control is the instrument for that work rather than another.** A gap, a radio, a checkbox, a written field, numbered chunks, a matching pool, four options, a chart whose cells are answered — each does one thing well and several badly. A defence that cannot be written means the shape is wrong, and the answer is a different shape rather than a weaker sentence. A defence that would read the same for the block beside it means one of the two was never chosen. "It is an activity, so it is a gap" is not a defence; "the student has to discriminate between two forms that both look right, which a gap cannot show" is.
- **Four questions come before any shape is chosen, and the shape is the answer to them**, not the starting point: **(a)** can these concepts be grouped or ordered so that each one explains the next? **(b)** how much of the student's success here depends on understanding the rule, how much on training the use until it is automatic, and how much on memorising an item — that mix decides whether the section needs explanation, repetition, recall, or all three? **(c)** is this the place to introduce, compare or remark on a synonym, antonym, homophone, homograph, false cognate or relevant idiom the roadmap's item brings with it? **(d)** given (a), (b) and (c), what is the best way to organise, display and teach it — and only then, which element does that?
- **Every sentence about the language is a statement of fact, and it is tested, not decorated.** One question decides it: **would a grammar written for teachers print this sentence as it stands, and would every example on the page agree with it?** A sentence that fails is rewritten as the plain statement when it does any of three things: it describes an effect instead of naming the word, form or rule it is about — it says what a word accomplishes instead of what that word is; it gives a word a meaning, a purpose or an action that word does not have; or it asserts something the page cannot check — an invented quantity, a fact true of only one employer, or a question standing where a statement belongs. No list of banned phrases is the rule, because the fault is structural: an action belongs to the thing that performs it, and moving it onto a thing that does not perform it is the fault whether or not anyone has said the sentence before. **A statement about the student is allowed and is written literally** — what the student will do with the item, when, and why it matters — while the same claim attached to the item itself is not. A title, an `h2`, an `h3`, an instruction and every item's wording are held to this test as the teaching prose is.
- **Write to the student in the plainest words that are still accurate.** A rule, a gloss, a note and an instruction are all held to the student's own vocabulary: a word used to explain another word has to be easier than the one being explained, and a phrase whose meaning needs a second explanation has been written one level too high. Where Portuguese and English share the word and the meaning, saying so is the shortest true explanation the page can give.
- **A note is read for what it adds.** A line left after an example earns its place by giving the student something to use on the next answer — a test, a mistake it stops, the word's real use, a phrase heard beside it. A line that says back what the example has just done is removed.
- **A sentence is written to be understood without the example under it.** The explanation states the rule in full; the example that follows shows the rule already stated. A paragraph that only becomes clear after the example has been read has taught nothing on its own, and an item that cannot be answered from the statement alone has been written from the example instead of from the rule.
- Where a lesson's subject *is* a figure of speech, an idiom or a false cognate, the page names it in plain words, says what it means and shows it in an example; the explanation itself never borrows the figure. A question, a stem and an option are held to the same test as prose.
- **1A writes the basic markup, and only the basic markup.** The frame of each section is written here: the `h2` that opens it, the `h3` that opens a block, the paragraphs and the lists, and the cells that hold them. **An activity is written as its words, not as an element**: its instruction, its numbered questions, its options and its keys — including the value of any attribute that carries lesson text, `data-answer`, `data-a` and `data-say`, because those values are the content — while the control itself and the element's markup are 1B's. Nothing about appearance is decided here: no widths, no `data-look`, no visual's markup, no frame. A block is opened where the division helps the student — it may set apart elements that must be read beside each other and kept distinct, two tenses side by side or a contrast — and it is never opened without need, because division without need is noise.
- **Then the whole section is divided into rows, and 1A writes the `.rows`.** The division follows the content: cells are grouped when the student reads them against each other — a rule with the exercise that tests it, two contrasts, a dialog with the notes that read it — and a cell with nothing to be read against stands alone in its row. **A row of more than one cell is a claim that those cells are read against each other, and the claim is one sentence long: what is read together, and why this pairing.** Where that sentence cannot be written, the row has one cell: a set of questions, a dialog, a chart, or an activity with nothing beside it to be read against all take the full line, and the white space beside them is the page's shape rather than a problem to solve. Sharing a row to fill a line, to balance a page or because two things are the same length is not a claim about content.
- **The row is marked as a row, so 1B can see the grouping it was given.** A row is written `<div class="rows">` whose direct children are its cells; a cell holds as many items as its content needs — one, two or several — stacked when they belong together. No cell is sized, spanned or painted here — 1B repairs the grouping and never re-invents it. **Questions may share adjacent cells inside their own activity** (`.qgrid stack`): two or three questions whose stems and options are short enough to sit side by side read faster as one set than as a column, while a question whose options are clauses takes the line under them, because a clause cannot wrap inside a share of the page. Which questions pair is decided by what each one asks the eye to compare, not by the count of questions in the block.
- **The prose is judged here, not measured later.** Read back what you have written and cut every sentence that pads, hedges, restates the one before it, or explains what the example beside it already shows. What is left states the rule, the reason and the contrast, and nothing else; a longer explanation is not a fuller one.
- **The ledger is read before the first heading is written.** Four separate rules, each with its own window, all read off the last rows: **one element the previous 3 lessons did not use** (every lesson); **no element in more than half this lesson's activity blocks**; **no teaching device in more than `max(1, floor(0.35 × its sections))` sections**; and **no four block subjects in a row that already ran inside one section of a recent lesson**. From lesson 10 the slower rules bite too — at least 60% of the palette inside the last 5 lessons, and the whole palette inside the last 10. A shape chosen because it was not on that list is still chosen for this lesson's content or not at all: the ledger forbids, it never nominates.
- This is the pass that decides whether the lesson is good. A block whose content is thin cannot be rescued by the shape it is given later, so the [COVERAGE] rules below are met on the words alone — and a section that lists what it will teach, or names the point without teaching it, has not been written yet.
### [1b] ARRANGEMENT — the shapes, once the words exist
- **The words 1A wrote become the element here, and this is where the additional markup goes.** 1A left every activity as its words together with its keys; 1B decides which of the map's elements answers it, copies that element's markup from the drawing, and puts the content inside it — the four-option questions become a `.qitem` carrying `data-a`, a set of words to put in order becomes chips over an answer line, a dialog's turns become a `.seq` with a keyed gap — and the unit that holds the control takes `data-activity="<that element's id>"`. Keys are moved onto the control, never invented or re-decided. Sections and blocks are neither added nor removed: their boundaries were 1A's, and 1B fills them.
- **Rows are grouped by what the student reads together, and a cell's size is not a reason to place it anywhere.** A cell holds what belongs together, and the cells beside it are chosen because they are read against each other — the rule and the exercise that tests it, two contrasts, the activity and the note that reads it — rather than because the two are the same length or because the line would otherwise be half empty. Sizing is the page's work: no `flex` or `width` is written on a cell, because the page sizes the line when it loads and an authored width is stale on the next screen. **Width goes to whatever needs it**: a cell holding a chart, a table or long answer lines takes its share first, and a block whose content is wide earns its neighbour only when that neighbour is read against it; otherwise the wide block takes the line. A row that still reads badly is repaired by moving content between its cells, by giving the wide cell the line, or by breaking the row.
- **A question's or a list's vertical space is never authored.** The solver sets the gap between a cell's numbered items and between a list's items, and it opens and closes it: the tallest cell in the row that cannot hold a question or a list is the height the others take, so a question cell or a list cell gains or loses height without the prose changing. A `<br>`, a `padding` or a `margin` written to push an item down is not written. The same rule fixes the width: a question cell is never narrowed past its widest item and a list cell never past its longest item — an authored `<br>` and the page's own wrapping stay, and the solver adds no break of its own.
- **A lone element at the end of a section** is centred or given the full width, whichever reads better.
- `data-look` is set now and only here. One tint and one outline per section at most; `data-look` changes the paint only and never marks importance.
- Each element's markup is copied from the example `extra/lesson1-The Capability Map.html` draws for it, never from memory. **The example is the default for what the element contains and where its text goes, and its item count is the example's own, never a count to copy.**

- **Every block opens with its `<h3>`.** The block's letter is drawn from that headline, so a block with no `h3` has no letter, no anchor and nothing to point at: one line, the block's point, never a topic label.
- **Text that introduces or applies to a whole section or block goes at the top of its respective container, and may be its own row.**
- **A section is one teaching idea and the practice that belongs to it, not one activity** — two blocks that teach the same thing belong in one section, and four sections that each teach half an idea are one section written badly. The count, the 1-to-6 range and the `sep:` defence are [1a]'s rule and are not restated here: a section is added only when a lesson puts a different teaching idea in it, and the ledger says which idea that was.
- **The page says what is true of the language, and 1B adds no prose of its own.** A sentence 1B writes or rewrites — an instruction, a caption, a line under a chart — is held to the three questions in [1a] exactly as the teaching prose is. Where a phrase is vague, name the words it means.
- **Where a page shows a difference, the difference is visible.** When the teaching turns on two groups that behave differently — the chart rows whose verb is `does` against the rows whose verb is `do`, two forms of a verb, two columns that answer different questions — the two sides may be told apart by appearance (colour, `opacity`, a heavier border) or by arrangement (each group read as a group), so the student sees which side the point belongs to without counting rows. Guidance, not a rule: pick whichever the chart's own shape makes cheapest, and a contrast the student cannot see has cost them the chart.
- **Every item the student answers is numbered**, `<span class="qnum">1.</span>`, and the number stands **beside the control it numbers** — in the same cell as the radio, the gap or the words, never in a column of its own. In an unscramble it sits at the head of the chips, not alone on the answer line; in a dialog it sits outside the bubble, on the side that faces the middle of the dialog (`position:relative` on the `.say`, the number absolute at `right:calc(100% + 8px)` on a right-hand speaker's turn and at `left:calc(100% + 8px)` on the left-hand speaker's — on a left-hand bubble a `right:100%` number hangs outside the dialog's own edge). The count runs through the activity block, so four items read 1 to 4 whatever their shapes. It is written as text rather than drawn by CSS so that the number survives print and can be named aloud.
- **A field is as wide as its answer.** `--gap-w` is **1.3× the longest accepted answer** (the field's own padding included), written in `em`, and there is no other cap: a short answer gets a short field, a long one gets a long field. What decides the row is the answer's length, not a number: an item whose answer needs more room than half the row takes **its own row, one item per row**, so the field fits and no block beside it is squeezed. A one-letter key sits on the 3em floor because a letter is not a word. A long question line gets the width it needs for the same reason: the row is arranged around the question, never the question wrapped to fit a row. The block that looks compressed is the symptom; the field that forced it is the fault. Never `100%` and never `calc()`: a field declared as wide as its block has stopped showing its answer.
- **The street map is one drawing, imported and never redrawn.** `extra/lesson1-The Capability Map.html` draws it once — nine places, each named on a sign: station, café and park across the top; bank, library and post office in the middle; bus stop, market and hotel along the bottom — with a MAP GEOMETRY comment giving the columns, the rows and the tick percentages that go with them. A lesson copies that `svg` whole (viewBox, roads, places, signs, labels and the table) and writes only its own `qstem` and its own tick labels; a place the drawing does not show is a place the question does not name. The drawing is capped at 573px, half of an in-block row, so it never grows to comic width beside a paragraph.
- **A comic is used only where a drawing is the content.** A comic is right when the thing being taught is something the student must SEE — a place, a face, a state, an action in a scene — and the drawing shows it without words. It is wrong when the panels contain sentences: a speech bubble with a question written in it, or a panel whose job is to hold text, is a text exercise in a picture frame, and the student reads the words and ignores the drawing. If the item can be written as a line of text, it is written as a line of text in a chart or a fill block; the comic is not a way to decorate a list. **Every drawing in a comic must be a clear, universally understood picture of the thing it stands for**: the object recognisable at a glance, drawn from the side a person actually sees it, with no invented symbol standing for an idea, and each `svg` carrying an `aria-label` that says plainly what is drawn.
- **A comic's size and its drawing's size are separate, and the 2 x 2 never re-arranges.** A comic is `<table class="chart comic" style="--comic-h:112px">` with two columns and one `<td class="strip">` per panel, so four panels are always two rows of two whatever the width — the table never reflows a row into a column, and a panel is never declared `display:block`, which is what turns the cells into stacked blocks. The width of the comic is the table's (capped at **573px**, half an in-block row, the same cap the street map takes) and the height of every panel is `--comic-h`, set once on the table. The drawing is an `svg` with a `viewBox` and **no `width`/`height` attributes**: the sheet gives it `width:100%` and the panel's height, and the svg's own `preserveAspectRatio` (the default, `xMidYMid meet`) scales it uniformly inside that box and centres it — so a comic made wider only adds margins left and right, one made taller only adds them above and below, and one made bigger in both grows the drawing. The answer line, when there is one, is written in the same cell under the `svg`.
- **A gap that answers a centered question is centered with it.** Where the question is written `text-align:center` and its gap sits on the line under it, the gap carries `margin-inline:auto` so the two read as one item; a gap under a left-aligned question stays left. The room above it is the sheet's, so no vertical margin is added.
- **The mode indicator has one name.** The auxiliary that fills the place between *who* and *what happens* is **the mode indicator** — `do`, `does`, `don't`, `doesn't` — and what it does is **carry the verb tense** (and the person with it); that is why the negative and the question are the places it appears. The modals (`can`, `could`, `would`) take that same place. On its own the base verb already carries the simple present (`I work`), and the `-s` is the third person singular conjugation (`she works`); when a negative or a question arrives, that `-s` moves onto the mode indicator and the main verb returns to base (`she doesn't work`). No page calls it *the little verb* or *the little word*: a coined name leaves the student holding a label with no word in it. The same rule governs every name a page gives a teaching point: *place*, not *slot*; *form*, not *shape*; the *past participle*, never a *third form*; no *ladder* and no *rungs*; a *meaning*, not a *shape*; the *quiz*, not a *check*; and a line of a conversation is a *line*, a *reply*, a *question* or a *statement*, never a *turn*. *Form* is a grammatical word — the forms of a verb, of a tense, of a word — and never a stand-in for "a way of saying something": when two sentences say the same thing at different lengths or in different registers, the prose names what each one is and says what changes. A word the book invents cannot be looked up, heard or recognised outside the page.
- **A dialog turn's side is its speaker's, never its place in the list.** Every `<li>` of a `data-mode="turns"` dialog carries `data-side="left"` or `data-side="right"`: the speaker who opens the dialog takes the left, the **second** speaker takes the right, and any further speaker joins the first on the left; a speaker keeps that side for the whole dialog. The same name never appears on both sides, and a speaker who answers twice stays where they were — the sheet alternates nothing. **A run of turns by one speaker carries the name once**: the `.who` is written on every turn and the sheet hides it on a turn that follows another by the same speaker.
- **A page that teaches a sound contains the sound.** Where the lesson's subject is how something is said — a vowel with no fixed sound, a letter that does not follow the rule, a word whose spelling misleads — the teaching blocks carry a `.listen` button speaking the words being taught (or the `.vz-play` player, where a recording is the point), and at least one item asks the student to hear it or say it. A page about sound with no sound on it describes the language instead of teaching it, and the student leaves able to repeat a rule they have never heard.
- **What is read here is the page's shape, not its heights.** A row with one cell and nothing beside it, a block whose only content is an instruction, a sentence left alone as a block — read from the file, and repaired there. **A cell that ends higher than the neighbour it shares a row with, and a headline cut short by the block that holds it, are read in [ALIGN] on the rendered page**, because a height guessed from a file is a guess about a scene nobody has looked at.
- **A chart that cannot fit its row.** The solver gives the chart its own width; if the row still reads badly, break the row or give the chart the line — never write a width on the cell. Nothing else is exempt: a dialog, a drawing or a timeline sits in its share like any prose.
- **How full the boxes are is read, then left alone unless a change can be named.** A cell or block filled to less than about half is a *candidate* for one change, and that change must be one you can justify in a line for the student: move it beside the thing it belongs with, let a drawing take the width it needs, or bring the item it explains into the same cell. If no such line can be written, leave it — white space under a short cell is a normal page, and content invented to fill a box is worse than the gap. Never rearrange items to even out space.
- The tests are the gate: an element that only repeats the sentence beside it, or whose removal would cost the student nothing, is not used. **A block of prose with no element is the normal case**, and an element with nothing purposeful to accompany it stands outside a block rather than being given one. A chart shows an example; the teaching is always a sentence, never a chart. **A chart's column header is content and is held to the same test**: it is written only when it names something the student has to tell apart — a contrast, a category, or the question the column answers (`Written / Said`, `Now / Past`, `Which one?`). A header that only names what a column obviously holds — `The sentence`, `What it means`, `The form`, `The piece`, `Letter` — is removed and the header row collapses to the 3px rule (`<thead><tr class="bare"><th colspan="N"></th></tr></thead>`, the same row the capability map's chart examples draw).
- The tools run here — `qa/pos.mjs` for the marks, `qa/audio.mjs` for a recording, `PronKey.render` for a key — and what they print is pasted, never retyped. **The pronunciation key is the only way a sound is shown on a page: no respellings, no capital stress, no invented notation.** If the dictionary has no entry for a word, write the key the way `PronKey` would write it and move on. The player a [1a] song section left a place for is built here.
- **The row is finished here.** Append to this lesson's line the elements it actually built, with a count for each block (`el:dialoggap:3,mc:1`), the quiz's elements (`qel:`), and the register score (`reg:in-voice/all`) judged **section by section** against the register's voice. The element that holds a control carries `data-activity="<its element id>"` — `chunks`, `stripgaps`, `chartanswer`, `dialoggap`, `mc`, `matching`, `correction`, `fill`, `dictation`, `flip`, `map` — which is the id of the markup box the builder copied it from, so the ledger and the page cannot disagree. `translation` is the one element with no box of its own: it is the correction or the dictation used to ask for a translation, and the block records `data-activity="translation"` when it does. A game is a skin over one of these and records the element underneath it. **A gap on its own does not qualify and should be avoided, but one or more can be used to diversify training inside other blocks** — it is keyed with `data-answer` like every other control on the page; it is only the ledger's count of activities that leaves it out.
### [1c] OPTION SETS — the last read before the page is rendered
- **Each option set is laid out by the length of its options, and the layout is a decision of the page.** One- or two-word options sit on one line (`data-layout="row"`); options of three or four words sit two by two (`data-layout="grid"` with `--cols:2`); options that are phrases or clauses stack, one per line, with no attribute at all. The stem and its options stay together in the cell they belong to, options under the question, never beside it and never pushed to the row's edge, and the column count is the one that stops a single short option wrapping alone. **A question that shares its activity's row with other questions is narrower than the page** — a set of three side by side has a third of it — so its four short options take the two-column layout even when each is one word, and an option stranded alone on a second line is the fault that shows the count was wrong for that width.
- **No width and no height is read here, and no line is cut to fit one.** A page that has not been rendered has no rendered line to cut: prose is written to be read, not to fill a box, and the pass that sees the box is [ALIGN], on the page itself. What is settled here is the option set's own shape — the lengths of its options and where its stem sits.
- With the page finished, add to the map page's **Learned during build generation** block one line for each mechanism this build proved and the block does not already hold — how a control is keyed, what an index counts, what an artifact must ship with the page, how a section is added to the map — written as what the machine does, never as a fault, a session or a date. A line already there is corrected in place rather than repeated, and nothing goes in that does not hold for all lessons: an item about this page alone belongs in the lesson, not in the block.



## [ALIGN] — the content balance pass, on the rendered page, before the push
- **When.** As the batch's last step (step 6): after every page is built and its checks are green, and **before** the commit and push. It reads the working tree through a local static server — the bytes that are about to be published — never a deployed copy that may still be the previous one.
- **It measures before equalization, and that is the whole point for heights.** `equalize.js` reads every cell at `align-self:flex-start` while solving, because a stretched cell's height says nothing about its content (`:199`); it then equalizes by redistributing widths (`:244`), by spreading a question cell's gaps (`:268`) and, in a two-cell row, by centring the shorter cell (`:277`). Each of those makes a lopsided row look level, so a height read from the finished page measures the solver, not the author. `npm run align -- --track=<track> --lessons=<range>` calls `EqualizeRows.clean()` — the engine's own "give me the authored page back" — holds each cell at its own height, and reads what each cell actually carries, at 1280 and at 1024px. Heights come from the authored page; **widths come from the solved one**, because the solved page is where a cell is squeezed.
- **A row is uneven when its two cells differ by more than 30px of content.** The tolerance is there because a dialog and a two-item question are not the same job; 30px is the difference a reader does not notice. A row of one cell has nothing to balance and is not measured.
- **A squeezed cell is a pairing fault, and it is read in the solved state.** Width is the solver's to give, and it gives it to whatever needs it: a cell holding a chart, a table or long answer lines takes its share first, and its neighbour can be left too narrow for a chip run or an answer line. That squeeze exists **only** after equalization — the authored page gives both cells half — so the pass reads the page twice: the solved widths (printed `~~`, as `wants 479px in 189px (chips on 6 rows)`), then `clean()` for the authored heights. **A cell short of width is repaired structurally**: the row is broken, or the wide cell is given the line. **A cell short of content takes content** — the case the activity has not asked for, the exception the section named, the longer clause — and that is the repair when a row of two is a real pairing and the shorter side simply carries less.
- **Inside an activity is read as well.** A `.qgrid` puts its questions in adjacent cells, so one question standing a hundred pixels taller than its neighbours is the same imbalance as a lopsided row: the pass prints each `.qgrid` whose items differ by more than the tolerance (`items 153 / 153 / 251 (d=98px)`), and the repair is a question moved out of the grid onto its own line, or two shorts paired and the long one left alone — never a question shortened to fit a share of the page. The answer line of a scramble is read the same way: an `input.gap` declared wider than the cell that holds it is what wraps the chips above it, and the pass names the block and both numbers.
- **The repair goes in the shorter cell, and it is content — but only after the pairing has been checked.** First read the row against the rule that made it: are these two cells read against each other? If the reason is size, balance or a filled line, the pairing was not a claim about content, and **the row is broken** — one cell, full width — which is the whole repair. Where the pairing is real, an activity takes another item of the kind it runs — the case it has not asked for, the exception the section named, the longer clause. A teaching cell takes the example, the contrast, the note, the related phrase or idiom the section stopped short of. **It may also take a picture**: open-licence photography is preferred to a drawing, cropped and scaled to what the cell's own content asks for, kept in `assets/` with its credit line under the figure. Rows are not capped: a row may be cut, its content redistributed, or a further `div.rows` added below with a block that belongs to the section, and the commit says which of the three it was.
- **Rewrapping comes last, and only after the content repair.** A line is not shortened or lengthened to reach a height as the first move: rewrapped prose is the same thin content moved around, and it can leave the row as uneven as it found it — the failure this ordering exists to prevent. Once the cell carries what it was missing, a line may be re-cut where it reads better *and* the height improves. A headline that comes out cut short — its block narrower than its words — is reworded shorter and never left cut; it is read here, on the same page, in the same pass.
- **The ledger is not rewritten**, with one exception: a block added here whose activity is a kind the row does not name gets that id in `el:`, because `qa/batchcheck` reads the ledger against the page.
- **The pass is re-run until it prints no row above 30px**, then `mapcheck`, `batchcheck --lessons=<range>` and `build:lessons` run again, and the batch is committed and pushed with the alignment stated in the commit message.
## [AUTHORING] - 

- Each lesson is imagined and generated in a unique and varied way, the order and type of its sections and blocks are never a standard - they are conceived independently as the optimal way to deliver the specific lesson and/or the specific elements within it. No lesson may reuse the structure of another, and no lesson repeats the structure of the page before it. **Every rule in this file is a condition the finished page must meet, and it is read on its own terms**: the examples inside a rule — a sentence, a markup fragment, a ledger segment — show the shape of the thing being asked for or the shape of the fault, and are never lesson content, never a sentence to copy onto a page, and never evidence that the rule does not apply to a case that is not written down.
- Teaching is sentences that explain and examples that show; a visual is one way an example is drawn, chosen because it answers a question the sentence cannot, never because a section is expected to have one.
- **The sentence that explains an activity describes the mechanic the control actually runs, in the direction the student works it.** Whether the prompt carries the answer and the student finds the word, or carries the word and the student supplies the answer, is the difference between two activities that look the same on the page; the instruction names which one this is, and it is written after reading the engine that runs the control, never from the shape's name or from the order of the markup. A card whose back is the prompt is turned to find its front, and the page says so in those words.
- **An activity asks a question the student can get wrong for a reason the lesson has taught.** A set of cards dealt as *verb → verb + -ed*, a matching whose every pair is the same suffix, a drill whose items all follow from one rule — each is a demonstration of the smallest thing on the page, and it spends the student's minutes on what they already do. At a level that knows the rule, the items carry the case that breaks it: the irregular form, the one that repeats a form the student expects to change, the pair that is confused. An activity nobody can fail is not training.
- **Every gloss, definition and translation a student is asked to accept is verifiable.** It comes from a dictionary or from the way the word is actually used, and a native speaker would sign off on it. A gloss may shorten a definition; it may never add a claim the word does not have, and it may never put the word with an object or in a collocation English does not use — a card back that reads plausibly but is not the word's meaning teaches an error that the activity then drills into memory.
- The tone and vocabulary described in the REGISTER is maintained throughout. The ROADMAP teaching concepts, vocabulary, and examples are thoroughly explored, explained, trained, and tested — there is no limit to distinct, useful teaching and/or training content: if the student is expected to need a lot of training to master a concept or memorize crucial vocab, then the lesson should reflect and fulfil that. Depth, thorough explanation (**clarity**, never filler or prose for its own sake) and training are better than less of them — all of it in an engaging and relevant lesson for the <TRACK>-REGISTER.md [PERSONA].
## [LEVEL] — the lesson number is a curriculum position, and it fixes the page's difficulty
- **This section outranks every other consideration of difficulty.** The roadmap says what the lesson contains; the register says whose voice and which world; this section says how hard each item is — and no phrase in the roadmap and no flavour in the register lowers it or raises it.
- **Everything the page asks the student to read, answer or produce — the prose, the prompts, the activities, the quiz — is authored at a level that is accessible but mildly challenging for the student who has arrived at that lesson.** Accessible: nothing depends on English the course has not taught, nothing is explained by a word the page has not defined, and the instruction is written in words that student can follow at this number. Mildly challenging: the page never prints the answer beside the question, and every item asks for one thing more than the student could do without thinking about it. Accessible alone teaches nothing; challenging alone cannot be read.
- **"STUDENT LEVEL" is assumed, and it is relative to the lesson's number and to the English concepts and vocabulary the course has taught up to that point.** **Ability grows with the lesson number**: lesson 1 assumes the student knows no English, and by lesson 50 the student should have achieved functional fluency. The page must read as the step it is — a lesson 12 that could be printed at 40, or a 40 that could be printed at 12, was not written for its number.
- **The number is both floor and ceiling.** The page may assume every concept, form and word the course taught through the lesson before it, and nothing else; and it must demand the work of a student who has had that many lessons.
- **Difficulty is what the student must do — never how rare the words are.** A page is hard when the student must hold a rule across a whole sentence, choose between forms that compete, move several things at once, produce rather than select, and notice where the rule does not apply. It is easy when the student fills one word per line with the answer printed beside it, however advanced the topic's name.
- **Difficulty rises with the number on the door, and rising is measurable.** From lesson 20 a teaching example carries a subordinate clause and a named circumstance, never a two-word frame; from lesson 26 it runs to at least twelve words and asks the student to hold one thing from its first half to its second; from lesson 34 a sentence may nest a condition inside another clause or change tense mid-sentence. The count of work rises with it: a quiz at 26 or later holds at least eight items across at least three shapes, at least one of them producing a whole sentence rather than choosing a word, and at least one that fails a student who learned only the main rule — the exception, the contrast, or the case the rule does not cover. An item at 30 whose answer is one known word, or a drill whose sentences could be printed at 10 with the nouns changed, is the page walking back to a level it has passed.
- **Portuguese is used to explain concepts and give direct translations only when the student's [LEVEL] is insufficient that they should be expected to understand the necessary explanation in English** — and the lesson number is the only measure of that level: the same explanation is Portuguese at 1 and English at 30. Portuguese — when used — is marked `.pt` for identification and italicization.
- **An inference about what the level forbids is not a rule.** Only this section sets difficulty, and it never limits how many words an item may hold or how long a phrase may be: a page whose items are all one word because the lesson number is low has invented a constraint nobody wrote.
- **A page can be advanced in content and beginner in difficulty, and that is a defect.** Reported speech at 44 is not a table of shifts plus one-word gaps: it is the system (what moves, why, in what order), the switch that turns the shift off, the exceptions, and the student producing paragraphs of relayed speech.
- **The explanation is not the material.** The prose that explains a concept or a vocabulary item may be plain: it should sit at the lesson's level, and it does not have to be advanced. What must be at the level is the English the student handles — every example sentence, quoted line, dialog turn, gap answer, drill item and quiz item. A page that explains reported speech elegantly around "I'm tired." is a beginner page wearing advanced prose, and it fails this section even when every paragraph reads beautifully.
- **The examples are also the register.** Those same sentences are written in the register's voice: in the REGISTER's scenes and with its own words from its lists, never in a neutral course voice that merely describes them. A block whose examples could be printed in any track is a register failure even when its topic fits the track.
- **What maps directly** onto Portuguese is cheap; what maps onto it and misleads is expensive; what has no counterpart is built from nothing. Frequency says nothing here: "descend" is cheaper than "go down" although it is the rarer word, and the present perfect costs this student more than the past perfect although it costs a native speaker less — the mapping breaks in one and holds in the other.
- **Sentence complexity is what the sentence asks the reader to hold at once** — a clause inside a clause, a tense that changes mid-sentence, a reference the reader must remember to the end, a form whose Portuguese counterpart does not match.
- **Importance can outrank level.** A concept the track cannot do without belongs in the lesson that needs it even when it is expensive, and then the support around it grows — more teaching before the item, more training after it. The item is not lowered and the level is not moved; the support adds teaching and training, and it never restores an earlier lesson's scaffolding.
- Optimize concept/element/content grouping/order according to the needs of the student. [Introduce, compare, or make note of] [synonyms, antonyms, homophones, homographs, false cognates, relevant idioms/expressions, etc.] that are relevant to the lesson content.
- Every (new word/form/concept) the student must understand is presented before it is used; if a block wants the student to *infer*, the page says so. 
- Teach the rule, the reasoning (the mental model), and its direct consequences.
- **A teaching point is explained past its rule.** Beside the rule, the reason and the Portuguese contrast, each point carries **the neighbour it is mistaken for** — the sentence the student would say instead, and the word in it that makes it wrong here — and **one note the student could not have inferred**: how often and where native speakers use the form, what the same idea sounds like in a mail as against a meeting, the words that travel with this one (*meet a deadline*, *miss a deadline*, *the deadline slips*), the false friend, or the small word whose presence changes the meaning of the whole line. The note is a fact about the language, never a remark about the lesson; a paragraph that restates the rule in other words is what [1a]'s prose test cuts, and a teaching section with no note has taught only what its heading promised.
- **Each point is shown at least three times, and the three do different work**: one example in its plainest setting, one where something around it changes what it means — a negative, a question, a second clause, another subject — and one where the rule does not apply or where the wrong form tempts. The examples live in the register's room with the register's people, and they do not share a frame: three lines with one subject and one verb are one example written three times. Where the lesson's word brings related phrases with it (*a supplier pays an invoice*, *a client settles an invoice*, *the invoice falls due*), the page names the two or three it will need and says how they differ.
- Multiple-choice options are shuffled so the right one is not always in the same slot. No copy-exercises: the student produces from memory or meaning,
- **A matching and an unscramble are dealt in a full shuffle.** In a matching, no row's letter is the meaning at that row's place in the pool; in an unscramble, no chip (word or phrase) sits at its own place in the sentence. Moving one item is not a shuffle — the whole order is re-dealt, so the answer is the only order the items are not in. The number on a chip is the display order, never the answer's order.
- **An item never asks for a judgement on an axis the page has not defined before the item**, and no invented terminology is used to name or classify a form: a term the student has not met is taught before it is used, and a term nobody outside a textbook uses is not used at all.
- **The options of an item match the lesson in concept and the level in length and linguistic complexity**: a one-word answer is not offered beside three-word distractors, and a distractor is wrong for a reason the page has already covered — never because it is absurd, foreign to the scene or obviously the odd one out.
## [COVERAGE] — the roadmap section is a floor, not a summary
- **Every concept, construction and example the roadmap section names is accounted for in the page**, and every vocabulary item it lists is used where the register licenses it. The lesson is not finished because the section has been mentioned: it is finished when each concept has been taught, contrasted, trained and tested.
- **The section's `Examples` are required teaching, not illustrations.** Each phrase the roadmap lists is put in front of the student as taught material: taught before it is trained, and reused wherever the lesson needs an example of the form it shows. They were chosen because they show the lesson's main points, so a page that swaps them for sentences of its own has taught something else — more examples may be added around them, never instead of them.
- **The vocabulary is the words the student must own at the end of the lesson, and it is chosen by importance, never by flavour.** Each listed item is a word the lesson teaches, trains and closes with; where two candidates compete, the more useful one wins — a pronoun, a common verb, or a word the student will use tomorrow outranks a word that merely illustrates the point. A word that only appears inside an example (the `at` of "I work at the mall", the `mall` itself) is explained on the page so the sentence is understood and is **not** a vocabulary item and is not tested. A concept the lesson teaches — a suffix pattern, a sound rule — is shown through whatever words demonstrate it; those words **are not part of the "vocabulary" for the lesson nor necessary to teach or train**, because they are there to make the concept visible. The mix across a track (about half its working words, a quarter everyday life, a quarter the wider world) describes what the course covers as it advances; it never licenses a flavour word ahead of a basic one, and the first lessons are the basics first.
- **A concept is not taught until the student could produce it unaided.** The five parts that get them there are the method in [TEACH → TRAIN → QUIZ], and every one of the five is required: a point with fewer than five has been mentioned, not taught, and a point with none of them has not been written yet.
- **Nothing is first met inside an activity.** Every word, form and idea an activity asks the student to answer for has already been taught or introduced — on this page, or by a lesson the course has taught. An activity may accompany the teaching it belongs to, and it may reuse what the page has just explained, but the first explanation of anything never appears inside it: an item that teaches while it tests is unanswerable for the student who has read nothing, and unmarkable as evidence for the teacher.
- **Thin is measured by consequence, not by length.** An explanation that leaves the student unable to say the sentence unaided is thin at any length; a short one that states the rule and its reason is not. Where a concept is expensive, its support grows — more teaching before it and more training after it — because importance outranks level.
- **The page ends by using every concept it taught on material the student has not seen**: mixed, new sentences, in the register's world — never the lesson's own examples again.

## [TEACH → TRAIN → QUIZ] — the three obligations, in this order
- **The method, in five parts, applies to every teaching point on the page** — a tense, a preposition, a word, a suffix, a way of ordering a sentence. Nothing in the list below depends on what the point is, and a point that has fewer than five has been mentioned rather than taught: **(a) the rule**, in one or two sentences, in words a dictionary would use; **(b) the reason** the language works that way, because a rule the student can justify survives a sentence it was not written for; **(c) what Portuguese does in the same place** — it matches (cheap), it misleads (expensive, and named as a trap), or it has no counterpart (built from nothing); **(d) one example** in the register's own scene, which shows the rule already stated rather than revealing it; **(e) training in which the student produces the point**, from memory or meaning, in sentences the page has not shown. The quiz closes the lesson.
- **Teach** the elements of its content thoroughly — each concept and vocabulary item the lesson owns, with the rule, its reasoning, its consequences and the Portuguese contrast where the mapping misleads — and present each before the student is asked to use it. **Train** what **was** taught: the student practices it, producing from memory or meaning, on material that is new to the page rather than a copy of the explanation. **Training may sit inside the teaching section it belongs to or stand in a section of its own** — the lesson chooses, for the flow its content wants, and neither shape is the default. **Quiz** at the end: the lesson closes with a quiz (the last section before the notebook) that tests the students understanding and memory of all the concepts and vocabulary that is new to the lesson - generating new phrases and not copying or repeating any of the taught or previously trained phrases - so that passing it requires having learned the lesson, not having read it.

## [MUSIC] — a section built on a recording, when the lesson uses one
- **The song is chosen by the lesson's structure, never by taste.** The line must contain the form or the vocabulary the lesson teaches, in a way that can be pointed at on the page. A line that merely paraphrases it is not a candidate, and a well-known song whose line teaches nothing is not one either. The phrase is found by web search — LRCLIB cannot search lyric text — and then proved with `--finds`, which prints the line number; a line number is never passed unproved.
- **Two runs, the second one pinned.** Run `qa/audio.mjs` once without `--out` to see which upload it paired (it checks the length within 2 s), then repeat with `--lrc-id` pinned, because the site's results move between calls and an unpinned run can pair a different edit of the same song.
- **The tool prints, the page pastes.** `qa/audio.mjs` writes `assets/<name>.mp3` itself and prints the figure with its `data-t` values, its `data-duration`, and the provenance row. The figure is `figure.vz-play viz` and it goes inside the block, under the block's own `<h3>` — the heading names the section's teaching point, while the song rides in the figure's `<h4>` and the performer in its `p.dim`, because a song title is not a heading. Nothing is retyped and **no `data-t` is ever edited by hand**: a highlight that fires early or late is moved with `--cue-shift`, an excerpt sitting wrong inside the recording is moved with `--early`, and either flag leaves the command that reproduces the page. On a lesson page the source is `../assets/<name>.mp3`, and the printed row goes to `assets/README.md`. The player script is already in `_shell.html`; nothing is added to the page for audio.
- **Music is a great teaching tool and should be used in many lessons where it is sufficiently relevant - it is an addition, it accompanies but does not take the place of needed teaching or training content.** It has a teaching point that its heading names, and it runs the lesson's own sequence on that line: the student predicts what they will hear, hears it, the line is marked and read, the rule is stated as it appears **in this line**, and the student then produces the same structure from words that are not the song's. The recording is evidence, never decoration — if the section would teach the same thing with the audio removed, it is not a section and the line was not relevant.

A page that fails the first cannot be taught from; a page that fails the second is a page of drills a student already knows. (Catches the lesson that is readable and empty, or unreachable even with help.)
